# PitchIQ 방송 중계 스타일 UI 개편 — 설계

## 배경

고정 데모 모드 전환(`2026-08-03-fixed-demo-mode-design.md`) 이후에도 UI가 여전히 범용 다크
대시보드 느낌이라 "야구스럽지 않고 직관적이지 않다"는 피드백을 받았다. 구체적으로 세 가지가
동시에 문제로 지적됨:
1. 화면 구성 요소(영상/예측카드/타임라인/통계카드)가 비슷한 크기로 나열돼 시선이 어디로 가야
   할지 안 정해짐 (위계 부재)
2. "FF 20% 신뢰도" 같은 숫자만 덩그러니 있어 이게 무슨 근거의 예측인지 감이 안 옴 (맥락 부족)
3. 모든 카드가 같은 톤(진한 네이비 배경 + 얇은 파란 테두리)이라 카드 종류가 구분이 안 됨
   (시각적 구분 부족)

## 목표

1. 전체 비주얼 방향을 "방송 중계·스코어보드 스타일"로 통일 (ESPN/MLB 중계화면 계열 — 굵은
   숫자 타이포, 스코어보드/오버레이 그래픽, 팀컬러 강조)
2. 세션 최초 진입 시 브랜드 스플래시로 실제 "랜딩" 순간을 만든다
3. 우측 패널의 정보 위계를 예측(핵심) vs 실측/현황(보조)으로 명확히 구분
4. 카드 종류별 색 구분으로 한눈에 성격을 알 수 있게 한다

## 비범위 (Non-goals)

- `session_state` 구조 변경 금지 (필드 추가는 허용, 기존 필드 의미 변경 금지)
- BiLSTM/YOLO 예측 로직, 영상 동기화(OCR/타임스탬프) 로직 변경 금지
- 2단 레이아웃(영상 `col_video` + 패널 `col_panel`) 골격 자체를 갈아엎지 않음 — 그 안의 카드
  구성·스타일만 재작업
- 다크 테마 기조 유지 (전역 규칙: 다크모드로 임의 전환 금지와 별개로, 이미 다크인 기존 방향을
  유지하며 팀컬러·골드 액센트로 생동감만 추가)
- 사이드바 구조(제목 / 경기 현황 / 구종 범례) 유지, 톤만 맞춤

## A. 랜딩 스플래시

현재 자동 로드 블록(`app.py`, `_DEFAULTS` 초기화 직후)은 동기적으로 데이터를 불러온 뒤 바로
대시보드를 렌더링해서, 기존 `_render_landing_hero()`가 뜰 틈이 없다(빈 상태를 거치지 않고
바로 로드 완료 상태로 넘어감). 이를 2단계 rerun 구조로 바꾼다:

```python
if not st.session_state._demo_auto_loaded and st.session_state.game_pk == "":
    if not st.session_state._intro_shown:
        st.session_state._intro_shown = True
        _render_intro_splash()
        time.sleep(1.4)
        st.rerun()
    else:
        st.session_state._demo_auto_loaded = True
        st.session_state.video_src = FIXED_DEMO_VIDEO_URL
        st.session_state.is_playing = True
        _demo_ok, _demo_msg = _load_game(str(FIXED_DEMO_GAME_PK))
        if not _demo_ok:
            print(f"[FixedDemo] 자동 로드 실패: {_demo_msg}")
```

- `_intro_shown` : `_DEFAULTS`에 `False`로 추가하는 새 세션 상태 키
- `_render_intro_splash()` : 신규 함수. `⚾ PitchIQ` 로고 + 태그라인 + "LIVE 데모 준비 중..."
  표시를 전체 폭으로 렌더링. 새 CSS 클래스(`.intro-splash`, `.intro-badge` 등)로 방송 인트로
  톤(큰 타이포, 은은한 펄스 애니메이션 — 순수 CSS `@keyframes`, JS 불필요)을 낸다.
- 첫 rerun에서는 스플래시만 그려지고 `st.rerun()`이 즉시 스크립트를 중단시키므로 사이드바·
  본문이 함께 그려지지 않는다 (깔끔한 랜딩 프레임).
- 두 번째 rerun부터는 기존 `_load_game()`이 실행되며, 그 안의 `st.spinner("Statcast 데이터
  수집 중...")`가 자연스럽게 "로딩 중" 다음 단계로 이어진다 (스플래시 → 스피너 → 대시보드).
- `_load_game()` 실패 시(`loaded == False`로 남음) 기존 `_render_landing_hero()`가 폴백으로
  뜬다 — 이번 개편에서 같은 톤으로 가볍게 리스타일만 하고 로직은 그대로 둔다.

## B. 방송 스코어보드 헤더

기존 `.scoreboard` 블록(팀명/점수/이닝/B-S-O 카운트)을 다음과 같이 강화한다:

- 팀 컬러 매핑 테이블을 하드코딩으로 추가: `TEAM_COLORS = {"NYY": "#0C2340", "LAD": "#005A9C"}`.
  고정 데모 게임(775300)은 항상 이 두 팀만 나오므로 이 두 항목이면 충분하지만, 매핑에 없는
  팀 약자가 들어와도 깨지지 않도록 기존 블루(`#60a5fa`)로 폴백한다. 점수 숫자·팀명
  언더라인에 적용.
- 점수 숫자 폰트를 한 단계 더 키우고(`.team-score` 확대), B/S/O 카운트를 원형 dot 대신
  사각 세그먼트(LED 전광판 느낌)로 교체.
- `.scoreboard`와 영상 영역 사이 여백을 제거해 시각적으로 한 덩어리(영상+스코어바)처럼
  붙인다. 진짜 영상 위 오버레이는 Streamlit 컬럼 레이아웃 특성상 z-index 제어가 불안정해
  시도하지 않는다 — 붙여서 오버레이처럼 "보이게"만 한다.

## C. 우측 패널 — 예측 카드를 시각적 히어로로

- "다음 투구 예측" 카드(`_predict_next` 결과를 렌더링하는 카드)를 다른 카드 대비 확연히 크게:
  패딩·폰트·테두리 강조(퍼플/골드 액센트, 아래 D 참고).
- 카드 상단 레이블을 "다음 투구 예측"에서 더 직관적인 문구로 교체하고, 신뢰도 배지 옆에
  근거 한 줄을 추가한다 — 예: `_bstatus == "done"`이면 "BiLSTM 모델 예측", 아니면 "통계 기반
  예측(BiLSTM 계산 중)". 새로운 계산 로직 없이 기존 `bilstm_status` 세션 값만 참조.
- "투수·타자" 패널과 "방금 던진 구종" 카드는 새 CSS 클래스 `.panel-secondary`로 격하:
  `.panel` 대비 폰트·패딩을 한 단계 줄여 명확히 보조 정보로 읽히게 한다.

## D. 카드 타입별 색 구분

카드를 두 그룹으로 나눠 배경/테두리 색을 분리한다:

- **예측 계열** ("다음 투구 예측", "방금 던진 구종") — 퍼플/골드 액센트
  (`border-color: rgba(167,139,250,.4)` 계열, 기존 `.badge-pred` 색과 통일)
- **실측/현황 계열** ("투수·타자", 사이드바 "경기 현황", 하단 `.stat-card`) — 팀컬러/네이비 톤
- **범례** ("구종 범례") — 중립 그레이 유지

각 카드 상단에 작은 아이콘 + 라벨(예: 🔮 예측 / 📊 실측)을 추가해 카드 성격을 항상 표시한다.

## 검증

- `streamlit run streamlit_app/app.py` 새 세션으로 실행
  - 최초 진입 시 스플래시가 짧게(약 1.4초) 보이고 이후 대시보드로 자연스럽게 전환되는지 확인
  - 스코어보드 헤더에 팀컬러·확대된 숫자·세그먼트 카운트가 반영됐는지 확인
  - 우측 패널에서 "다음 투구 예측" 카드가 시각적으로 가장 눈에 띄고, 근거 문구가 표시되는지
    확인
  - 예측 계열/실측 계열/범례 카드가 색으로 구분되는지 확인
- 회귀 확인: 오늘 고친 자동 로드(`_load_game`, `_demo_auto_loaded`)·자동재생(`is_playing`,
  `autoplay`/`mute`) 동작이 스플래시 추가 이후에도 그대로 동작하는지 확인
- 브라우저 스크린샷으로 개편 전/후 비교
